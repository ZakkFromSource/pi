---
description: Refresh the tracked inventory of global and fork-managed Pi extensions
---
Update the tracked Pi package inventory belonging to the source checkout used
by the `pie` launcher. Do not assume the current working directory is that
checkout.

First locate the `pie` launcher (`Get-Command pie` on PowerShell or
`command -v pie` in a POSIX shell), inspect its wrapper, and follow the path it
uses for `pi-test.sh`. Treat the directory containing `pi-test.sh` as the
checkout root. Confirm that the root contains both `package.json` and
`customizations/README.md`; if it does not, stop without editing anything.
The inventory target is `customizations/pi-packages.txt` inside that root.

Build the inventory from these sources:

1. Run `pie list` and record only entries under `User packages`; do not include
   packages from another project's `Project packages` section.
2. Inspect `~/.pi/agent/extensions` for files, symbolic links, or directory
   junctions whose resolved targets are inside the checkout. Record their
   checkout-relative targets as globally linked fork extensions.
3. Inspect the tracked files under `.pi/extensions` in the checkout. Record each
   top-level extension file or extension directory as a project-local fork
   extension. Ignore untracked files.
4. Inspect `customizations/goated-ai-skills/cli.ts`. If it still passes
   `getGoatedExtensions(args)` as `extensionFactories`, record
   `customizations/goated-ai-skills` as a launcher-integrated extension.

For each npm package, read the installed package's `package.json` from the path
reported by `pie list` and record its exact installed version using this format:

```text
npm:package-name@1.2.3
npm:@scope/package-name@1.2.3
```

Preserve already-pinned git sources and local-path sources exactly as reported.
Use forward slashes for checkout-relative paths. Sort entries lexically within
each section. The complete file must use this format:

```text
# Pi extension inventory
# Generated by /extentionlist.

## User packages
<reproducible package sources>

## Globally linked fork extensions
<checkout-relative targets linked from the global extension directory>

## Launcher-integrated extensions
<checkout-relative extension integration directories>

## Project-local fork extensions
<tracked checkout-relative extension files or directories>
```

Leave a section empty when it has no entries. Do not remove any section. If an
npm version cannot be determined, retain the source reported by `pie list`
without inventing a version and report the unresolved entry.

Modify only `customizations/pi-packages.txt`. Do not install, remove, update,
enable, or disable packages. Do not read or expose credentials. After editing,
read the inventory again, compare every section with its source, and report
additions, removals, version changes, and unresolved versions concisely.
